Frequently asked questions

Short answers. Exact limits.

Disk safety, verification scope, and current limits.

What does Bootable write?

ISO, IMG, and RAW images; XZ, gzip, Zstandard, and bzip2 archives; and extracted FAT32 Windows installer media. Sources can be local files or downloads from the built-in catalog.

Can it erase an internal disk?

Bootable rejects fixed disks, the running system disk, partitions, read-only media, and write plans that do not fit the expanded image. It accepts whole USB-attached or explicitly removable disks, then rechecks the stable target identity immediately before writing. This is alpha software: always verify the physical device named in the review.

Why does writing require administrator access?

Operating systems restrict raw disk access. Interactive writes elevate only a fixed, protected helper after the write plan is approved. The desktop, TUI, catalog, downloads, and image parsing stay unelevated.

What does “verified” mean?

  • A publisher checksum match proves the source bytes match the publisher's checksum file.
  • Raw read-back proves the written range matches the expanded source stream.
  • A Windows boot-tree audit checks UEFI files, installer payloads, split-WIM parts, and FAT32 limits.

None of these proves that every firmware or operating-system installation will succeed.

Can it create a Windows 11 USB on Linux or macOS?

Yes. Bootable creates GPT or MBR media with one FAT32 partition and splits an oversized install.wim. Linux needs wimtools; macOS needs wimlib. Current Windows media targets UEFI, not legacy BIOS.

Which Windows setup choices are available?

Hardware-requirement bypass, offline-account path, named local account, host regional settings, privacy defaults, automatic BitLocker control, quality-of-life policies, CA 2023 boot files, SkuSiPolicy revocations, and S Mode. Each choice appears in the reviewed write plan.

What happens if I cancel a write?

Bootable stops at a controlled boundary, terminates media tools it started, and marks the target incomplete. Do not boot or reuse that media. Start a full write again.

Are the desktop and terminal apps equivalent?

Yes. GUI and TUI use the same labels, section order, plans, progress stages, cancellation, errors, and retry behavior. Both call the same core and protected helper.

What is not implemented?

Legacy BIOS helpers for constructed Windows media, Linux persistence, Windows To Go, DOS media, and multiboot. Windows RAW backup is also unavailable. See the roadmap before depending on a planned feature.

Why does the operating system warn about Bootable?

The alpha executables are not code-signed and the macOS build is not notarized. Release archives include SHA-256 sidecars and GitHub build provenance, but those do not remove SmartScreen or Gatekeeper warnings.

How should I report a failed write?

Use the alpha report. Include version, platform, interface, image name and version, target model and capacity, failed stage, and exact error. Remove disk serial numbers, usernames, and private paths.
